# Security Policy

## Reporting a vulnerability

Please report security issues privately to the project owner through the contact method already published by the project. Do not open a public issue containing credentials, session details, production URLs with secrets, or private school information.

Do not upload real student data, result files, database exports, or private workbooks when reporting an issue. Provide a minimal, sanitized reproduction instead.

## Supported versions

Security fixes are applied to the current default branch and active deployment. Older revisions are not separately supported.

## Repository safety

Never post passwords, API tokens, private keys, cookies, database credentials, or confidential school/student data in issues, pull requests, discussions, or attachments.
